# 个人资料编辑实施计划

## 已确认范围

在现有 dev 分支保留全部未提交修改。延续 Emil 暖灰、白卡、金色选项设计，实现可保存的本人资料编辑。选项无单/多选提示和勾，学历补初中；职业、兴趣、本人和对方信仰为文本；双手交握左手/右手。后台原文展示，选择当前语言文字后原文保存，不新增数据库多语言结构。协助者邮箱编辑原文、展示继续脱敏，不增加解释文案。

个人资料为默认内页，排在我的动态之前；第四个底部导航改个人资料及人物图标。页首最多两张叠放图片，前头像、后资料照片；无可用照片使用默认头像。未完善资料可点击提示进入编辑。

所有新编辑弹层从下往上进入、从上往下退出，遮罩淡入淡出；确认/取消/系统返回的退出完成后才卸载。减少动态效果设置被尊重。此规范写入工程约定供后续弹层使用。

## 实现任务

1. 字段模型与六语言文案：声明分组/字段，草稿独立，保留未知旧值，仅差异生成部分更新；生日与数字验证；完成度不强制可选字段。先运行数据行为回归。
2. 后端：完善 selfIntroduction/bio 部分写入，新文本信仰与旧数组兼容；只验证本次变化；owner 权限、隐藏字段和工具保留。测试先行，不改数据库结构。
3. 展示/导航：共享详情按需显示编辑入口；人格值原文展示；导航人物图标与六语标签。
4. 编辑界面：总览、独立分组草稿、保存失败重试、未保存退出确认；跨端弹层、安全区、键盘、返回、过渡动画。
5. 本人页集成：头像叠放、资料提示、默认个人资料，保存后更新详情和缓存，避免旧请求覆盖新状态。
6. 验证：模型与后端回归；真实 H5 运行时用拦截API验证只改指定字段、六语、错误重试、取消返回、过渡、320px；顺序构建 H5/微信/App。真机验证单独报告，不自动发布。

## 任务分工与验收

- 前端模型、后端保存、共享展示/导航分别由独立代理负责，主代理负责编辑界面和集成。
- 仅上述文件范围内修改，测试 API 使用本地拦截，不写真实用户资料。
- 不新增父母/推荐类型虚构字段，不修改账号登录邮箱，不修改获赞数据。
- 工具标签本地化，后端资料内容原文。保存不发送旧整表中的 status/careers 等未编辑字段。
- 产出在 dev 保持可审核，不提交、合并或发布。
