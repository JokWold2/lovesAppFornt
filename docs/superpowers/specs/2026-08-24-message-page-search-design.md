# 消息页搜索设计

## 目标

在“消息”页提供轻量搜索入口。用户点击右上角搜索图标后，搜索输入框从右向左展开；可实时筛选当前已加载的互动消息、群聊名称与群聊最后一条消息。

本期不新增后端全文检索接口，也不搜索尚未加载的群聊历史正文。

## 页面状态

### 默认状态

- 顶部首行左侧显示“消息”，右侧显示搜索图标。
- 下方按现有顺序展示互动消息、管理员待审核项和群聊列表。

### 搜索展开状态

- 点击搜索图标后，搜索容器以右侧为锚点向左展开，时长 `220ms`，使用缓入缓出曲线。
- 图标过渡为关闭按钮；搜索输入框自动获得焦点。
- “消息”从首行移动至搜索框下方，使用不超过 `180ms` 的位移与透明度过渡，避免突变。
- 输入框包含搜索图标、占位文案“搜索消息”，并支持清空当前输入。

### 搜索收起状态

- 点击关闭按钮或清空并失焦后，输入框由左向右收起。
- 标题平滑回到首行原位置。
- 收起时清空关键词并恢复完整列表。

## 筛选规则

关键词会进行首尾空白清理，并以不区分大小写的包含匹配筛选：

1. 互动消息：匹配“互动消息”或其摘要。
2. 待审核私聊申请：匹配其固定标题和摘要；仅管理员可见。
3. 群聊：匹配群名称或最后一条消息摘要。

空关键词显示完整列表。无任何匹配项时，在列表区域显示“暂无匹配消息”。搜索不会改变未读红点、时间、点击进入群聊和五秒轮询刷新逻辑。

## 组件与数据边界

- 修改 `pages/notice/notice.vue`：维护 `searchOpen`、`searchKeyword`，从现有 `notifications`、`chatGroups`、`requests` 计算筛选后的展示列表。
- 不修改后端 API、数据库或群聊详情页。
- 不引入第三方搜索组件；使用 uni-app 原生 `input` 与现有 `uni-icons`。

## 动画实现约束

- 展开与收起使用 CSS `transition`，不使用定时器强行切换布局。
- 搜索输入框通过 `max-width`、`opacity` 和 `transform` 实现右向左扩展；避免 `display: none` 导致动画丢失。
- 标题容器保留稳定高度，使用 `transform` 与 `opacity` 过渡，减少列表跳动。
- iOS、Android App 和微信小程序使用同一套 rpx 尺寸与 CSS 动画逻辑。

## 验收标准

- 点击搜索图标时，输入框有可见的右向左展开动画，标题同步平滑下移。
- 文字输入后，群名、最后一条消息、互动摘要均可被实时筛选。
- 图片、未读角标、群头像、最后消息时间与原有点击跳转保持正常。
- 搜索无结果时显示空状态；关闭搜索后恢复完整列表。
- 文字搜索、展开/收起动效和空状态均有自动化回归测试。
