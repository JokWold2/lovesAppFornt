# LovesApp H5 视口与安全区适配设计

日期：2026-08-31  
状态：已完成方案讨论，等待规格复核

## 1. 背景与目标

LovesApp 的 H5 页面目前混用 `100vh`、页面级 `overflow: hidden`、`position: fixed` 和多套安全区写法。在移动浏览器中，地址栏、底部工具栏、横竖屏与软键盘会持续改变实际可视区域，而 `100vh` 不一定同步变化，造成以下问题：

- 群聊消息区域无法稳定上下滚动；
- 群聊输入栏在 iPhone Chrome 等环境中落到可视区域之外；
- 详情页评论栏、固定操作栏或最后一段内容被浏览器工具栏遮挡；
- 底部弹层高度不稳定，弹层内容无法滚动或背景跟随滚动；
- 不同页面各自修补，行为逐渐分叉。

本次目标是在不改变微信小程序和 App 行为的前提下，建立统一的 H5 可视高度与安全区基础能力，并迁移高风险页面。目标浏览器为：

1. iPhone Safari；
2. iPhone Chrome；
3. Android Chrome；
4. 微信内置浏览器。

## 2. 非目标

- 不重做现有页面视觉风格；
- 不改变导航、聊天、评论或上传等业务接口；
- 不修改小程序和 App 的既有键盘、滚动与安全区逻辑；
- 不为桌面端增加新的响应式布局体系；
- 不以全局强制覆盖 `uni-page-body` 的方式接管所有页面滚动。

## 3. 方案选择

采用“统一 H5 视口层 + 按页面类型迁移”的方案。

不采用逐页替换 `100vh` 的方式，因为该方式无法统一解决软键盘、固定底栏和弹层问题。也不直接覆盖 `uni-page-body`，避免影响普通长页面、下拉刷新、TabBar 以及非 H5 端。

## 4. 基础架构

### 4.1 H5 视口工具

新增 `utils/h5Viewport.js`。该模块只在 H5 环境安装，负责读取并发布可视区域信息：

- 优先使用 `window.visualViewport.height`；
- 不支持 `visualViewport` 时回退到 `window.innerHeight`；
- 监听 `visualViewport.resize`、`visualViewport.scroll`、`window.resize` 和横竖屏变化；
- 使用 `requestAnimationFrame` 合并同一帧内的重复更新；
- 读取失败时保持上一次有效值，不阻断应用启动或业务请求。

模块向根元素写入：

- `--app-viewport-height`：当前实际可视高度，单位为 CSS 像素；
- `--app-viewport-bottom-offset`：布局视口底部到可视视口底部的遮挡距离，最小为 `0px`。

模块必须提供可独立测试的纯计算函数；DOM 事件安装与数值计算分离。

### 4.2 公共 H5 布局约定

在 `App.vue` 中增加仅 H5 生效的公共布局类：

- `.app-h5-screen`：全屏页面容器。高度使用 `--app-viewport-height`，并扣除 uni-app 的 `--window-top`；
- `.app-h5-scroll`：全屏页面中的独立滚动区，使用 `flex: 1`、`min-height: 0`、纵向自动滚动和触摸惯性滚动；
- `.app-h5-fixed-bottom`：固定底栏，结合 `--app-viewport-bottom-offset` 与 `env(safe-area-inset-bottom)`；
- `.app-h5-sheet`：底部弹层，最大高度由真实可视高度决定，内部列表独立滚动。

CSS 变量尚未初始化时依次回退到 `100dvh` 与 `100vh`。页面模板可以保留公共类名，但对应样式和运行时监听仅在 H5 构建中生效。

### 4.3 数据流

```text
浏览器工具栏、横竖屏或软键盘变化
                  ↓
       h5Viewport 读取可视区域
                  ↓
          更新根元素 CSS 变量
                  ↓
全屏页 / 独立滚动区 / 固定底栏 / 弹层重新布局
```

## 5. 页面迁移范围

### 5.1 全屏独立滚动页面

首批迁移：

- `pages/chat/chatRoom.vue`；
- `pages/moments/momentDetail.vue`；
- `pages/market/marketFeed.vue`；
- `components/legal/LegalDocument.vue`。

这些页面使用真实可视高度。顶部信息区和底部输入/操作区不参与内容滚动，中间内容区独立滚动。

### 5.2 固定底部操作栏页面

首批审查并迁移：

- `pages/index/auctionDetail.vue`；
- `pages/searchPerson/searchPerson.vue`；
- `pages/my/myLifeShow/myLifeShow.vue`；
- `pages/index/index360.vue` 中的 H5 固定控件。

固定底栏必须避开浏览器工具栏、软键盘和底部安全区；正文必须保留与底栏实际高度相匹配的底部空间，确保最后一项内容不被覆盖。

### 5.3 底部弹层

首批迁移：

- `components/profile/ProfileLikesSheet.vue`；
- `components/chat/GroupMemberSheet.vue`；
- `components/chat/MemberPickerSheet.vue`；
- `pages/account/accountCenter.vue` 的语言选择弹层；
- `pages/notice/chatRequestReview.vue` 的审核弹层。

弹层最大高度使用真实可视高度。弹层标题与操作区保持可见，列表区域独立滚动；滚动弹层内容时不得带动背景页面。

### 5.4 普通长页面

登录、个人中心、资料编辑、消息列表、市场列表和群管理等普通页面继续使用浏览器原生页面滚动，只统一最小可视高度和底部安全区，不设置固定高度或全局滚动锁。

迁移时只处理确认存在遮挡风险的页面，不进行无关样式重构。

## 6. 群聊页专项行为

群聊页是本次适配的最高优先级验收项，必须满足：

- 群聊标题和群信息保持在顶部；
- 输入栏始终位于实际可视区域底部；
- 中间消息列表可以用触摸手势连续向上和向下滚动；
- 滚动到顶部时继续加载更早消息，并保持加载前后的阅读位置；
- 五秒轮询新消息时，用户正在查看历史消息不能被强制拉回底部；
- 仅在用户接近底部、发送新消息或点击“回到最新”时滚动到底部；
- 软键盘弹出时只压缩消息列表可用高度，不遮挡输入栏；
- 收起键盘、切换横竖屏或浏览器工具栏变化后自动恢复正确高度；
- 小程序继续使用原有 `scroll-view` 与键盘高度逻辑。

H5 消息滚动只保留一个实际滚动容器和一套滚动监听，避免模板事件与手动 DOM 监听重复处理同一次滚动。

## 7. 安全区与键盘规则

- 底部内容使用 `env(safe-area-inset-bottom)`；旧版 `constant()` 只作为既有兼容回退，不作为新代码主路径；
- 全屏 Flex 页面中的输入栏优先处于文档流底部，不使用 `position: fixed`；
- 普通长页面的固定操作栏使用公共底部偏移变量，并为正文增加等高占位；
- 键盘高度不得在 H5 中同时通过视觉视口和组件外边距重复补偿；如果 H5 已由 `visualViewport` 收缩，则不再叠加同一份键盘高度；
- 页面恢复、浏览器返回和横竖屏切换均触发一次视口同步。

## 8. 异常与降级

- `visualViewport` 不存在时使用 `innerHeight`；
- `innerHeight` 无效时由 CSS 使用 `100dvh`，再回退到 `100vh`；
- 所有计算结果均校验为有限非负数；
- 事件监听初始化失败只记录非敏感警告，不影响页面启动；
- H5 视口适配不得改变接口调用、鉴权状态或业务数据。

## 9. 测试策略

### 9.1 自动化测试

- 纯函数测试：可视高度、底部遮挡、无 `visualViewport` 回退、负数归零；
- 事件测试：地址栏、键盘、窗口尺寸和横竖屏变化触发重新计算；
- 布局契约测试：公共 H5 类存在，且高风险页面使用正确页面类型；
- 群聊回归测试：输入栏在滚动容器外，消息区为唯一滚动容器，顶部加载与回到底部逻辑保留；
- 非 H5 回归测试：小程序条件分支和原有 `scroll-view` 行为保持；
- 执行现有前端 Node 测试与 H5 构建。

### 9.2 浏览器验收

在 iPhone Safari、iPhone Chrome、Android Chrome 和微信内置浏览器验证：

- 地址栏展开与收起；
- 软键盘弹出与收起；
- 竖屏与横屏切换；
- 页面首次进入、浏览器返回和重新进入；
- 长内容滚动到顶部与底部；
- 固定底栏、最后一项内容和底部弹层的可见性。

群聊页还需验证消息列表的 `scrollTop` 能随手势变化、输入栏矩形始终位于视觉视口内、轮询期间历史阅读位置不变。

## 10. 验收标准

- 四类目标浏览器不存在输入栏或固定操作栏被浏览器工具栏遮挡的问题；
- 群聊消息区可稳定上下滚动，并符合第 6 节全部专项行为；
- 普通长页面保留原生滚动，不因全局高度规则被锁死；
- 底部弹层内容可滚动，背景不跟随；
- H5 自动化测试和构建通过；
- 现有小程序相关测试通过，且小程序/App 的页面布局未被 H5 专用逻辑改变。
